## Risks

- **uv version.** Local uv is 0.12.5; CI pins 0.13.6. A lockfile written by the older uv could fail `uv sync --locked` in CI. Mitigation: check the `uv.lock` diff (B1 step 2). If CI fails on `--locked`, regenerate with the CI version (`uv self update 0.13.6`, or `uvx uv@0.13.6 lock`) and push again.
- **Wrong database by accident.** `.env` points at `localhost:5433`, which is `devdigest-postgres`. A bare `uv run pytest` would try to create a database and create and drop tables there. Mitigation: the four values on every command; Open point 3.
- **Frontend CI red window.** Between the B2 merge and the frontend regeneration merge, frontend `api-types` fails. Mitigation: H2.
- **Local setups break after B1.** A developer's dev server uses `daily_game_challenge` only after they update `.env` and recreate the volume. CI is not affected. Mitigation: the AC-8b note.
- **No branch protection.** Nothing stops a merge with red CI. Check all four jobs by hand.

## Rollback

- **B1:** revert the squash commit in a PR. Anyone who already recreated a local volume keeps a `daily_game_challenge` database; they point `.env` back. Local data is test data.
- **B2:** revert the backend PR **and** the frontend regeneration together, backend first, or frontend `api-types` turns red again. Revert the platform `CONTRACTS.md` commit.
